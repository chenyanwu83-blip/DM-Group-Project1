## 三、预期问答（V5.0 要求：2+1 且**含 1 道 bagging/boosting 题**）

1. **【bagging/boosting · 必备】Ling showed AdaBoost + SMOTE winning on sick with F1 0.937. Did boosting help on credit-g as well?**
   → No — and that is our winner-flip. On credit-g the best ensemble is **Bagging + SMOTE at F1 0.548, AdaBoost + SMOTE only 0.501** — both 5–10 points below the main-matrix champion, logistic regression with the 5:1 cost matrix (**0.597**); the holdout agrees (0.543 / 0.500 vs 0.587). Mechanism: boosting re-weights the hard examples. On sick — sparse nominal attributes, nearly separable, 94:6 — that sharpens the boundary. On credit-g — dense mixed attributes, 70:30, weak signal — the "hard" examples are mostly noise, so re-weighting chases noise. And neither ensemble has a cost-sensitive channel: their total cost is 0.80–0.93, all worse than lr_cost's 0.514. Ensembles cannot substitute for cost information. （出处：`docs/A7x_ensemble_creditg运行记录_v1.0.md` §关键发现 1–3）

2. **【领域题】Why do the tree models get ordinal codes while logistic regression needs one-hot? Isn't ordinal simply wrong for nominal data?**
   → For a tree, a split is "code ≤ k?" — any order works, because a few splits can isolate any subset of categories; one-hot would spread the same information over 61 sparse columns and dilute the split gain (and random forest's random feature subsets would often draw uninformative dummies). For a linear model, ordinal codes become a numeric scale: "purpose = car" is treated as *larger* than "purpose = furniture" — a fake order the model takes at face value, which bends the decision boundary. That is also why the ordinal LR branch failed to converge within 1,000 iterations while the one-hot branch converged in 55. The attribution control — ordinal codes with standardised numerics, F1 0.415 ≈ 0.406 — confirms the gap is the encoding, not the scaling. （出处：`results/a6_onehot_comparison.csv` 三行）

3. **【整体设计题】Why evaluate with the official 5:1 cost matrix instead of just F1?**
   → F1 weights a missed default and a false alarm equally; the bank does not — missing a bad loan loses the principal, rejecting a good one only loses interest. UCI's cost matrix encodes that as 5:1, so cost = (5·FN + FP) / N. It changes decisions: ZeroR scores 0.70 accuracy but cost **1.5** (300 missed × 5 / 1,000); plain LR costs **0.884** (159 missed); LR with class_weight 5:1 costs **0.514** — recall jumps 0.47 → 0.86 while accuracy *drops* 0.75 → 0.65. Judged by accuracy it looks worse; judged by the bank's own loss it is the best model. That is RQ1's cost dimension and RQ2's accuracy trap in one example. （出处：`results/all_metrics_v1.csv` creditg_lr_plain / lr_cost / zero_ref cv10 行）

**加练（时间富余再背）**：*Why are the encoding-experiment t-tests uncorrected?* → A6 is a two-arm, pre-specified contrast with one primary comparison, reported as a fold-level paired *t* (n = 10) and explicitly flagged uncorrected; the main matrix's 12 pre-specified comparisons use Holm correction (C5). Both p-values (0.021 / 0.008) would survive a two-test Bonferroni (α = 0.025) anyway.
- *Do the Apriori rules validate the random forest?* → No — it is a **field-level partial echo**, not validation: all three RF top-3 fields (credit_amount 0.141 / duration 0.107 / checking_status 0.107) do reappear among the six retained rules, but the strongest rule itself (duration-q5 + savings<100, confidence 57.3%, lift 1.91) shares **only duration** with the top-3, and the two analyses are not independent evidence (RF fits 700 training records, Apriori runs on all 1,000). Say "echo the same fields", never "validate / verify the forest" or "explains the top-3 ranking". （出处：`src/e_apriori/e4_rf_feature_importance.csv`、`src/e_apriori/e3_selected_rules.csv`、`src/e_apriori/e4_interpretability_comparison.md`）
