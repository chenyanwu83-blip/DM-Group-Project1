## 两条评估协议

### 分层10折交叉验证：cv10

```python
StratifiedKFold(n_splits=10, shuffle=True, random_state=42)
```

- 同一数据集、同一原始行顺序的所有模型和策略，共用相同的10折划分。模型参数与随机种子事先锁定。
- 本次脚本保存 `results/cv_folds_credit-g.csv`、`results/cv_folds_sick.csv`，其中 `row_idx` 是原CSV的0起始行位置，`fold_id` 是1到10。
- 每折只在训练部分拟合预处理、分类器及采样器；验证折不参与插补、编码、缩放参数拟合或 SMOTE。
- 如果阈值需要选择，在该折的训练部分内使用额外内层验证，不能用该折验证标签选择阈值。
- D2 提议统一使用 `np.std(values, ddof=0)`，与仓库 C1 的 `scores.std()` 一致；这不是分工方案明定的 ddof，请 C/A/B 确认后再冻结：[C1 当前代码](https://raw.githubusercontent.com/chenyanwu83-blip/DM-Group-Project1/main/PreExperiment.py)。
- 八个指标分别报告10折均值和标准差，不用10折混淆矩阵合并后计算的F1冒充“折均值F1”。混淆矩阵另报10折计数之和。

## 正类、混淆矩阵与概率方向

混淆矩阵行是真实类别，列是预测类别；统一顺序是 `[负类, 正类]`：

```text
             预测负类   预测正类
真实负类        TN        FP
真实正类        FN        TP
```

credit-g：FN 为 bad 被预测成 good；FP 为 good 被预测成 bad。sick：FN 为 sick 被预测成 negative；FP 为 negative 被预测成 sick。

用 `classes_` 定位正类概率列，不默认 `[:, 1]`。D2 将真实标签映射为“正类=1、负类=0”，再用正类概率计算AUC；此方式与显式正类口径一致：[scikit-learn AUC 文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html)。

建议调用：

```python
metrics = compute_metrics(
    y_true, y_pred, pipe.predict_proba(X_valid),
    pos_label="bad", dataset="credit-g", classes=pipe.classes_,
)
```

sick 改成 `pos_label="sick", dataset="sick"`。如模型内部使用0/1编码，应将真实标签、预测标签及 `classes_` 一致映射回原项目标签后调用，不只更改 `pos_label`。

## 指标口径

| 模板指标名 | 含义/公式 | 实现 |
|---|---|---|
| accuracy | `(TP+TN)/N` | `accuracy_score` |
| precision | `TP/(TP+FP)`，正类精确率 | `precision_score(..., zero_division=0)` |
| recall | `TP/(TP+FN)`，正类召回率 | `recall_score(..., zero_division=0)` |
| f1 | 正类Precision与Recall的调和平均 | `f1_score(..., zero_division=0)` |
| auc | 正类概率对正负类的ROC排序指标 | 真实标签映射0/1后 `roc_auc_score` |
| kappa | 校正随机一致性后的分类一致性 | `cohen_kappa_score` |
| balanced_accuracy | 两类召回率的平均 | `balanced_accuracy_score` |
| macro_f1 | 两类F1的等权平均 | `f1_score(labels=[0,1], average="macro")` |

以上函数口径按 [scikit-learn 指标文档](https://scikit-learn.org/stable/modules/model_evaluation.html)；本项目额外明确以下边界处理：

- 模型没有预测正类：Precision置0并标记 `precision_undefined=True`，不能伪装成“没有问题的0”。
- 真实评价数据没有正类：Recall置0并标记；AUC不可算、Balanced Accuracy置空并注明。
- 未提供概率：AUC置空并注明，禁止用预测标签顶替概率，禁止以0冒充不可计算。
- Kappa在退化边际分布下不可计算时置空并注明。
- 模板保存数值列，不将 `0.8000 ± 0.0100` 合为字符串。显示表另行排版；保存尽量保持完整精度。
- 每个指标带 `*_n_valid`；如果10折中某折不可计算，标注不完整，均值只作为有效折描述，不宣称完整10折均值，标准差留空。

## credit-g代价公式

```text
cost = (5 × FN + 1 × FP) / N
```

仅对credit-g填报，N是本次评价样本数，不是训练集人数。sick全部 `cost` 列留空，不跨数据集比较代价数值。该方向与组内credit-g配置约定一致：[credit-g 代价配置](https://github.com/chenyanwu83-blip/DM-Group-Project1/blob/main/configs/spec_creditg.md)。

CV：`cost_mean/cost_std` 是逐折归一化代价的均值/标准差；`cost_pooled` 是先加总10折FN、FP后按总评价数计算的代价。分折大小不相等时二者可以略不同，不互相替换。Holdout：`cost_mean=cost_pooled`，std留空。

代价评价公式不是“给预测结果加权”的训练代码；C在训练时的 `class_weight` 是另外一件事。
